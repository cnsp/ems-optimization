## Colour‐Tier Definitions (Precinct Demand)

Several figures classify Manhattan's 25 precincts into three demand tiers:

| Tier | Colour | Rule | Meaning |
|------|--------|------|---------|
| **High** | Red (`#C0392B`) | crashes/day >= Q75 (4.8) | Top 25 % of precincts |
| **Medium** | Blue (`#5B8DBE`) | Q25 <= crashes/day < Q75 | Middle 50 % |
| **Low** | Green (`#27AE60`) | crashes/day < Q25 (2.0) | Bottom 25 % |

Thresholds are derived from the 25th and 75th percentiles of the
`crashes_per_day` column computed in `data/processed/demand_lambda_precinct.csv`
(hourly rate x 24).

## Precinct Demand Figures — Detailed Trace

### Data Flow

```
data/raw/Motor_Vehicle_Collisions_-_Crashes_20260223.csv
        │
        ▼  (scripts/demand_modeling.py / notebooks/02_eda)
data/processed/crashes_manhattan.csv          ← filtered to Manhattan
data/processed/demand_lambda_precinct.csv     ← per-precinct hourly rates
        │
        ├──▶ fig_precinct_demand.png           (original bar chart)
        ├──▶ precinct_demand_rates_improved.png (improved with legend)
        └──▶ precinct_demand_heatmap.png       (spatial choropleth)
                │
                ▼  (downstream)
        ┌───────────────────────────────────┐
        │ Optimization models use the same  │
        │ demand_lambda_precinct.csv as      │
        │ the demand weight (d_j) in the    │
        │ objective function of P2           │
        │ (demand-weighted allocation).      │
        │                                   │
        │ Simulation engine uses per-precinct│
        │ rates to generate NHPP arrivals    │
        │ via arrival_generator.py.          │
        └───────────────────────────────────┘
```

### Colour Coding Explained

The three-colour scheme communicates demand intensity at a glance:

- **Red (High)**: Precincts 19, 18, 14, 1, 17, 13, 10.  These seven precincts
  account for a disproportionate share of total Manhattan crashes and drive
  the demand-weighted optimisation to concentrate EMS units nearby.

- **Blue (Medium)**: Precincts 5, 25, 34, 20, 23, 33, 32, 6, 9, 7, 24, 28.
  These precincts have moderate demand and benefit from spillover coverage
  from units staged at high-demand neighbours.

- **Green (Low)**: Precincts 30, 26, 22, 50, 52, 114.  Low-demand precincts
  (often park-heavy or residential) receive fewer optimised units but still
  meet coverage thresholds because of their proximity to other staffed
  firehouses.

### Downstream Impact

1. **Optimization** (`src/ems_readiness/optimization/models.py`): The
   `demand_weight` column from `demand_lambda_precinct.csv` is the `d_j`
   coefficient in the demand-weighted allocation (P2) objective function.
   High-demand precincts receive more weight, pulling units toward them.

2. **Simulation** (`src/ems_readiness/simulation/engine.py`): The
   `crash_rate_per_hour` column drives per-precinct NHPP arrival intensity.
   High-demand precincts generate more incidents, stressing nearby units.

3. **Policy Evaluation**: Comparing P0 (uniform) with P2 (demand-weighted)
   reveals how much response time improves when allocation follows the
   demand distribution shown in these figures.

4. **CBD Analysis**: The heatmap's CBD boundary overlay shows that high-demand
   precincts cluster in Midtown (Pcts 14, 18, 19), supporting the decision
   to analyse CBD-specific scenarios separately.
