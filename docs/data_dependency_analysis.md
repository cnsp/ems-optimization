## 4. Proposed Architecture Assessment

### 4.1 The Proposal

> **Only `raw/` and `reference/` data from the repo; all processed/intermediate data generated by notebooks; serialized artifacts for reuse; seed-controlled reproducibility.**

### 4.2 Feasibility Verdict: **Feasible with caveats**

#### What works perfectly

- **Tier 1–3 data is fully reproducible.** The generation chain `raw → processed` is deterministic. Given the same raw CSV inputs and boundary GeoJSONs, the audit scripts + demand modeling will always produce identical outputs. No randomness is involved in spatial filtering, crash subsetting, or lambda table computation.

- **Distance matrices are deterministic.** Pure math from coordinates — no randomness.

- **SeedManager is already in place.** The project has a well-designed `SeedManager` class with per-component seed derivation, `configs/reproducibility.yaml`, and support for component overrides. Simulation results (Tier 4–6) are reproducible given the same seeds and processed inputs.

#### Caveats

1. **Two large raw files are NOT in the repo** (`Motor_Vehicle_Collisions_*.csv` at 536 MB, `Police_Precincts_*.csv` at 3.6 MB). These are gitignored for good reason (size). A new user must download them separately. This is the **critical external dependency** — without these, nothing downstream can be generated.

2. **The `*.pkl` files in `raw/` are misplaced.** `manhattan_geom.pkl` and `cbd_geom.pkl` are generated artifacts from `audit_step1_boundaries.py`, not raw data. They should either be in `processed/` or regenerated on the fly. Currently tracked in git — this is redundant since they're trivially derived from the tracked GeoJSONs.

3. **Processed files are currently git-tracked despite gitignore.** Nine processed files were force-added (`git add -f`). This creates a confusing state: gitignore says ignore them, but they're tracked. Under the proposed architecture, these should be removed from tracking.

4. **No single orchestrator script.** The generation chain requires running 6+ scripts in the correct order. There's no `make all` or `pipeline.py` that runs Tier 0 → Tier 6 end-to-end.

5. **`data_processing.py` referenced in Makefile doesn't exist.** The Makefile's `data` target calls `src/ems_readiness/data_processing.py` which is missing. The actual processing is done by the `audit_step*.py` scripts.

6. **`crashes_manhattan.csv` (99 MB) is expensive to regenerate.** Processing the 536 MB raw crashes file takes significant time. A user would need to do this once, then reuse the parquet version.

## 6. Recommendations

### 6.1 Immediate (Low effort, high impact)

1. **Remove processed files from git tracking:**
   ```bash
   git rm --cached data/processed/*.csv data/processed/*.json data/processed/*.geojson
   git rm --cached data/processed/*.parquet  # if any were tracked
   git rm --cached data/raw/manhattan_geom.pkl data/raw/cbd_geom.pkl
   git rm --cached data/manifests/data_audit_summary.csv
   git commit -m "chore: stop tracking generated processed data"
   ```

2. **Update `.gitignore`** to also cover:
   ```
   data/processed/*.json
   data/processed/*.geojson
   data/raw/*.pkl
   data/manifests/*.csv
   ```

3. **Create `data/raw/README.md`** documenting how to obtain the two large CSV files (NYC Open Data URLs, expected filenames, expected row counts for verification).

### 6.2 Short-term (Medium effort)

4. **Create a pipeline orchestrator** (`scripts/run_pipeline.py` or enhance the Makefile):
   ```
   Step 1: audit_step1_boundaries.py    → pkl files
   Step 2: audit_step2_firehouses.py    → firehouses_clean/manhattan.csv
   Step 3: audit_step3_precincts.py     → precincts_manhattan.geojson
   Step 4: audit_step4_crashes.py       → crashes_manhattan.csv/parquet
   Step 5: demand_modeling.py           → lambda tables
   Step 6: (distance matrix generation) → distance_matrix*.csv
   Step 7: run_optimization_comparison  → optimization results
   Step 8: run_verification.py          → verification results
   Step 9: run_validation_pilots.py     → validation results
   Step 10: run_production_v2.py        → Extended Fleet Analysis results
   ```

5. **Fix the Makefile** — point the `data` target at the actual audit scripts or the new orchestrator.

6. **Eliminate the pkl intermediaries.** Have `audit_step2/3/4` read the GeoJSONs directly instead of requiring pre-pickled geometries. This removes a fragile intermediate step.

### 6.3 Long-term (Nice to have)

7. **Serialize expensive intermediate objects** (e.g., `crashes_manhattan.parquet`) with content hashes so the pipeline can skip steps when inputs haven't changed.

8. **Add a `--verify` flag** to the pipeline that checksums all generated files against known-good values (for the default seed=42 run).

## 7. Example End-to-End Workflow (Post-Migration)

```bash
# 1. Clone the repo
git clone <repo-url> && cd ems-optimization

# 2. Setup environment
make setup  # or: pip install -r requirements.txt

# 3. Download external data (manual step — documented in data/raw/README.md)
#    Place these in data/raw/:
#      - Motor_Vehicle_Collisions_-_Crashes_20260223.csv
#      - Police_Precincts_20260223.csv

# 4. Generate ALL processed data from raw (deterministic, no seeds needed)
make data   # or: python scripts/run_pipeline.py --step data

# 5. Run optimization (deterministic — LP solver, no randomness)
python scripts/run_optimization_comparison.py

# 6. Run simulation experiments (seed-controlled, reproducible)
python scripts/run_verification.py
python scripts/run_validation_pilots.py
python scripts/run_production_v2.py
#   → All use SeedManager(master_seed=42) from configs/reproducibility.yaml
#   → Identical results every time

# 7. Open notebooks to explore/visualize
jupyter lab notebooks/
```

### Reproducibility Guarantee

| Stage | Reproducibility Mechanism |
|-------|--------------------------|
| Raw → Processed (Tiers 1-3) | **Deterministic** — no randomness involved |
| Optimization (Tier 4) | **Deterministic** — LP/MIP solver with fixed parameters |
| Simulation (Tier 5) | **Seed-controlled** — `SeedManager(master_seed=42)` with per-component derived seeds |
| Statistical Analysis (Tier 6) | **Deterministic** — operates on fixed simulation outputs |

With `master_seed=42` (the default), any user running the full pipeline on the same raw data will get **bit-identical results** for Tiers 1-4 and **statistically identical results** for Tier 5 (same seeds → same random streams → same simulation outcomes).
